## Post as published

Two critical AI infra bugs, one shared mistake: trusting localhost.

LMCache, the KV-cache layer many teams run under vLLM, has CVE-2026-105192, rated 9.8 by JFrog and disclosed October 7. In multiprocess mode its ZeroMQ socket has no authentication and unpickles a message before checking it, so one message runs code. Official container images run it as root. Versions 0.3.9 through 0.5.5 are affected, with no fixed release yet. The default binds to localhost, but the project's own Kubernetes example listens on every interface.

DeepSeek Harness, the coding-agent shell that passed 215,000 GitHub stars in weeks, had CVE-2026-82533 (CVSS 9.4). Its local API trusted the Host header, and its sandbox blocked file writes but left loopback open. One shell command from inside the sandbox switched the session to full access with approvals off. Fixed in 0.1.2-alpha.1.

My take: "it only listens locally" is a deployment detail, not a security control. Authenticate internal sockets, never unpickle anything that came off a network, and sandbox the network, not just the disk.

Are the services in your inference and agent stack authenticated to each other, or only firewalled?
